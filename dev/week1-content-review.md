## 2. 씬별 상세

### #1~2. 시티로 출발 / 관광객 모드 (사건 전 케미)
- 포즈 선택 루프, 징크스 대사("오늘은 아무 일도 없을 거야" — 복선), 팝업 전시 발견까지.
- 게임적 장치 없음, 순수 텍스트 선택(결과 분기 없이 flag만 기록: `w1-photo-style`, `w1-jinx-pick`, `w1-last-pose`, `w1-angle-pick`). **현재 이 flag들은 이후 씬에서 전혀 참조되지 않음** (§7 참고).

### #3. 전시장 자유 조사 (VN, 도입만)
- 원래 있던 10개 핫스팟 선택지 루프는 전부 미니게임(#4)으로 이전됨.
- 남은 건: 입장 대사 4줄 + (신규) 직원 안내 4줄 + 티키타카 9줄 + 마지막 한 줄 → 미니게임行.
- 이 씬 자체는 flag/effect가 전혀 없는 "순수 무드" 파트.

### #4. 전시장 둘러보기 (미니게임 — 그리드 핫스팟)
- 핫스팟 10개: 카메라/회중시계/K-01(필수, 다회화형)/접수대(필수)/태그/전용문/팸플릿/방명록/천장카메라/출입구(필수).
- 필수 3개는 진행을 막지 않고(§20 게임오버 없음 원칙), 완료 후 "관찰 보너스" 조건(선택 3개 이상)만 가른다.
- K-01만 vnPlayer 재사용한 11줄짜리 발견 대화, 나머지는 1줄 반응 + 토스트.
- 종료 시 `week1-scene-004`로 직행(하드코드 `location.href`).

### #5. 도난 발생 (VN → 미니게임 START)
- 직원이 도난을 알아채고 사진 7장을 건넴. 케미 라인 유지("진짜 탐정 같네" 등).
- `MINIGAME START` 텍스트로 끝나고 `nextSceneId: week1-scene-004-minigame`.

### #6. 사진 속 인물 찾기 (미니게임 — 확대/팬)
- 사진 7장(10:41/10:43/10:45/10:47/10:48/10:50/10:53), 핀치줌으로 인물 태그.
- 반복 목격 3인(윤민아/애드리언/레오, 아직 이름 비공개 — 옷차림으로만 서술) + 얼굴 없는 인물 1회 = 총 8회 목격.
- 스페셜 타겟 4개: 명찰 클로즈업(E-K01) / 렌즈 반사(E-M00) / 진열장 문 열림(E-K01) / 빈 받침대(E-K01).
- `REQUIRED_TOTAL = 12` (목격 8 + 스페셜 4) 전부 찾아야 완료.
- **주석 불일치**: 코드 주석은 "사진 6장"이라고 두 번 언급하지만 실제 `PHOTOS` 배열은 7장(§7-1 참고).

### #7. 사진 분석 마무리 (VN)
- 5장을 시간순으로 배치하는 choice 체인(오답 시 짧은 반응 후 재시도) + 사건 발생 시간대 추정(10:44~10:48, 좁게/넓게 틀리면 재시도).
- `E-TR1` 획득. "사진에 제일 많이 나온 사람부터" → #8로 자연 연결.

### #8. 용의자 선별 및 현장 재조사 (VN, 신규 확장 씬)

- 단계 B: 필수 재조사 2개(태그 위치 변화 E-H01B, 먼지 자국 E-H05) + 선택 재조사 3개(전용문 E-H06/방명록 E-H07/직원·카페·관광객 추가 질문 E-SEL1~3).
- 단계 C: 첫 가설 4지선다 — **정답 없음**, 어떤 걸 골라도 다음 대사로 넘어가되 `w1-first-hypothesis` flag만 기록. 이 flag는 §16 코멘트대로 "이후 지수 대사에 살짝 반영" 예정이었으나, **실제로 참조하는 코드가 없음**(§7-2 참고).

### #9~10. 윤민아 1차 / 애드리언 1차 심문 (VN, 각 4라운드)

## 7. 재조정 전 확인할 이슈 / 불일치

1. **#1~2의 flag가 죽어있음**: `w1-photo-style`, `w1-jinx-pick`, `w1-last-pose`, `w1-angle-pick` — 전부 setFlag만 되고 참조하는 코드가 없다. 케미용 콜백을 나중에 넣거나, 정리해서 없애는 게 나을지 결정 필요.
2. **사진 개수 주석 vs 실제 불일치**: `dev/minigame-photo-zoom/index.html`의 설계 주석은 "사진 6장"이라 적어놨지만 `PHOTOS` 배열은 실제로 7장(10:41/43/45/47/48/50/53)이다. 문서만 안 맞는 건지, 사진 하나를 빼려던 흔적인지 확인 필요.
3. **#8 첫 가설 flag(`w1-first-hypothesis`) 미사용**: 코멘트에는 "이후 지수 대사에 살짝 반영"이라 적혀 있으나 실제로 참조하는 곳이 없다. 재조정 시 실제로 반영하거나, 설계 의도를 접을지 결정.
4. **#15 사건 재구성에서 `question-case-solution`을 그 자리에서 바로 resolved 처리**: 같은 화면에 "사건 재구성 완료"와 "미해결 연결점(M.K.)"이 같이 뜬다. 서사적으로는 "부분 해결"에 가까운데 질문 상태는 완전 resolved라 트래커만 보면 다 풀린 것처럼 보일 수 있다.
5. **증거 코드 중복 `E-000`**: 0주차 `evidence-accommodation-keycard`(숙소 카드키)와 1주차 `evidence-k01-early-inscription-note`(K-01 사전 관찰 메모)가 같은 코드 `E-000`을 쓴다. 케이스 파일 UI에서 코드로 검색/정렬한다면 충돌 가능성 있음.
6. **`E-K01` 코드가 4개의 서로 다른 evidence id에 재사용됨**(명찰/문열림/빈받침대/인물목격 8건). 의도된 "K-01 상태변화 계열" 묶음으로 보이나, 다른 코드들은 대체로 1:1이라 일관성 검토가 필요.
7. **재조사(§8) 선택 증거가 심문 정답 목록에 이중 등재**: 예) `evidence-staff-tag-position-before/after`가 애드리언 R4와 레오 R5 양쪽의 정답 후보로 쓰인다(의도된 재사용 — §9 코멘트에 명시돼 있음. 문제라기보단 재조정 시 "이 증거를 안 모으면 두 심문 모두 막히는지" 동선 재확인 포인트).
8. **씬 #3(자유 조사)과 #4(그리드 미니게임) 사이의 정보 중복**: #3의 신규 티키타카는 케미 전용이라 괜찮지만, 원래 있던 hotspot 대사가 미니게임으로 완전히 옮겨가면서 VN 단독으로만 플레이할 경우(스킵 시나리오) 어떤 정보가 빠지는지 별도 확인 없음.
