## 경제·옷가게·옷장 시스템 (신규 — *The Missing Key v1* §4/§5/§14 P0+P1 구현)

포인트(P) 재화, 완성 코디 프리셋 상점, 옷장 착용 시스템의 기반 계층을 새로 구현. 수사 진행에는 절대 관여하지 않고(포인트 지급/차감 없음), 비수사 미니게임·평일 콘텐츠의 장기 보상 재화로만 쓰인다는 설계 원칙을 그대로 따름.

## 탐색 허브 프레임워크 (신규 — *The Missing Key v1* §7/§14 P2 프로토타입)

반자유 탐색 허브(장소 이동 → 인물 행동 메뉴 → 대화 주제 상태)의 재사용 가능한 엔진과, 그 위에 얹은 첫 실제 콘텐츠(1주차 Phase 1 관광 파트, §12.2)를 구현. **기존 1주차 23개 씬(순차 대사)은 건드리지 않음** — 이 허브는 별도 신규 화면(`/dev/explore/`)이며, 아직 기존 스토리 진행과 자동으로 연결되어 있지 않다.

### 신규 상태/데이터 파일
- `dev/state/explorationState.js` — 현재 주차/단계/장소, 장소 해금·방문 기록, 상호작용 상태(§7.4의 7단계 `locked/new/available/in_progress/exhausted/updated/resolved`를 override + 계산식으로 구현). 핵심 규칙("새 증거·사실로 이전에 끝난 대화가 `updated`로 재오픈")은 `refreshInteractionsByFact`로 구현하고 Playwright로 직접 확인함.
- `dev/data/locationDefs.js` — 1주차 Phase 1 장소 6곳(서큘러키/오페라하우스/하버브리지/더 록스 골목/더 록스 옷가게/전시장 입구). 배경 이미지는 기존 관례 그대로 `/dev/upload` 업로드 파이프라인을 그대로 재사용(장소 `id`가 곧 배경 에셋 키).
- `dev/data/interactionDefs.js` — 각 장소별 2~3개의 신규 단문 상호작용(§12.2가 서술하는 "배·관광객·버스커 관찰", "건물 감상·사진", "다리·추억 대화", "골목 탐색·팝업 전시 발견" 등)을 실제 대사로 새로 작성함. 증거 제시 반응 규칙(`presentEvidenceRules`, §14.8)은 아직 없음 — 이 시점엔 사건이 아직 안 일어나서 제시할 증거 자체가 없기 때문에 의도적으로 비워둠.
- `dev/caseFileState.js`의 `saveSlot`/`loadSlot`이 explorationState도 함께 스냅샷/복원하도록 확장.

### 신규 화면 — `/dev/explore/`
지도(§7.2)/장소(§7.1)/인물 행동 메뉴(§7.3: 말 걸기·질문하기·증거 제시·인물에 대해 묻기·관찰하기·그만두기)/대화 재생을 **별도 라우팅 페이지 3~4개가 아니라 뷰 전환이 있는 단일 페이지**로 구현(허브 상태를 세션스토리지로 왕복시키지 않아도 되게). CASE FILE 메뉴(`caseMenu.js`)를 그대로 재사용해 저장/설정/옷가게/옷장에도 접근 가능. `/dev/`에 "탐색 허브(프로토타입)"로 진입 링크 추가.

### Playwright로 확인 및 실제로 잡은 버그
- 종료 위치(exit) 버튼이 상단 고정바 뒤에 깔려 실제로는 탭이 안 되던 CSS 버그 — 발견 즉시 수정(`.exit-row`를 `margin-top:auto`로 하단 정렬).
- 첫 진입 장소(부팅 파라미터로 들어온 장소)에는 `firstVisitFlag`가 적용되지 않아 `visitedCircularQuay` 같은 옷가게 해금 플래그가 영영 안 켜지던 버그 — 부팅 로직이 UI 이동과 동일한 `moveTo()`를 타도록 리팩터링해 수정.
- 옷가게(라우트형 장소) 진입 시 `mkShopReturnUrl`이 실제 현재 위치가 아니라 최초 부팅 시 URL을 가리키던 버그(SPA라 주소창이 안 바뀜) — `ExplorationState`의 현재 위치/단계로 직접 URL을 구성하도록 수정, 상점에서 "돌아가기"를 누르면 실제로 있던 장소로 복귀하는 것까지 확인함.
- (마무리 패스) CASE FILE 메뉴의 미션 타이틀이 허브 안에서 장소를 이동해도 갱신 안 되던 표시 버그 — `caseMenu.js`의 `missionTitle`이 함수도 받을 수 있도록 확장(문자열을 넘기는 기존 `dev/game/index.html` 쪽은 그대로 동작, `dev/explore/index.html`만 `() => 현재 장소명` 함수로 전환)해 수정, 메뉴를 열 때마다 최신 장소명이 뜨는 것까지 확인.
- 이후: 장소 이동 → 인물 메뉴 → 질문하기(NEW 배지) → 대화 재생 → `exhausted` 전환 → 가짜 사실 추가 → `refreshInteractionsByFact` → `updated` 재오픈 → 옷가게 라우트 이동 → 복귀까지 전 구간을 실제 클릭으로 검증.

### 기존 스토리와의 연결 (§12.2 "전시장 진입 강제 시점" 소프트 게이트)
`week1-scene-002`(관광객 모드) 자체의 사진 포즈 루프·각도 선택은 **손대지 않고 그대로 유지**했다. 마지막 줄("팝업 전시 발견")만 강제 진행 대신 선택지로 바꿨다:
- "지금 들어가요." → 기존과 동일하게 그대로 `week1-scene-003`행 대사 이어짐 (기존 동작 100% 보존).
- "조금 더 둘러보다 갈래요." → `discoveredPopupExhibition` 플래그를 세우고 `returnToExploration` 이펙트로 탐색 허브(`w1-circular-quay`)로 진입. 허브에서 자유롭게 돌아다니다 `빈티지 전시장 입구`에 도착하면 "전시장에 들어간다" 버튼(장소 정의의 신규 `enterSceneId`/`enterSceneLabel` 필드)으로 `week1-scene-003`에 정확히 합류한다.
- `week1-scene-002 → 허브(순회) → week1-scene-003` 전체 경로를 Playwright로 클릭까지 실제로 실행해 검증함 — 씬 전환 시점의 `?line=` 리줌 기능(기존 세이브/불러오기 기능 재사용)으로 포즈 루프를 건너뛰고 바로 분기 지점부터 확인.

### 하버 포토 미니게임 (신규 — §12.3, 비수사·포인트 지급)
`/dev/minigame-harbour-photo/` — 배경(오페라하우스/하버브리지) 선택 → 포즈 선택 → 3라운드 타이밍 미니게임(움직이는 마커가 초록 구간에 있을 때 셔터) → 등급(S/A/B/C) 산정 → 기본 250P + 등급 보너스(최대 150P)를 `EconomyState.claimReward`로 `first_clear_only` 지급. S등급이면 `harbourPhotoGradeS` 플래그를 세워 `outfit-w1-photo-perfect`(이전 세션에 카탈로그만 정의되어 있던 상품) 해금 조건을 실제로 채울 수 있게 됨. 이 미니게임에서 찍은 사진은 수사 증거로 절대 쓰이지 않도록 `evidence-*` 계열과 데이터/rewardId를 완전히 분리했다(§12.3 요구사항).

탐색 허브의 오페라하우스·하버브리지 두 장소에 "사진 찍기 (하버 포토)" 상호작용을 새로 연결했다 — `interactionDefs.js`에 `type: 'minigame'` + `route`를 얹는 방식으로, 대사 재생 대신 실제 미니게임 페이지로 이동하고 끝나면 정확히 원래 있던 장소로 돌아온다(옷가게와 동일한 `mkShopReturnUrl` 왕복 패턴). Playwright로 클리어→보상→복귀, 그리고 재플레이 시 포인트가 중복 지급되지 않는 것(`+0P (이미 받은 보상)`)까지 확인.

### 용의자 자유 순서 탐문 (신규 — §12.6, Phase 4)
`week1-scene-006`(윤민아)/`007`(애드리언)/`008`(레오) — 각각 4~6라운드짜리 기존 심문 씬 — 를 **한 줄도 고치지 않고** 자유 순서로 방문 가능하게 만들었다. 방법:
1. 세 씬의 내부 `condition`을 전부 확인해 서로 의존성이 없음을 검증(006의 유일한 조건은 그 이전 씬 005에서 세운 가설을 참조할 뿐, 007/008 완료 여부와 무관).
2. `week1-scene-005b`(다니엘 최초 진술) 종료 지점에 `nextSceneId`를 추가해 신규 탐문 허브(Phase `W1_SUSPECT_INTERVIEWS`, 장소 4곳: 탐문 거점 + 윤민아/애드리언/레오 각자의 스팟)로 진입시킴.
3. 각 스팟의 유일한 상호작용은 "심문하기"(`type: 'minigame'`) — 대사를 쪼개지 않고 해당 씬 전체를 그대로 실행하는 하나의 단일 진입점. 윤민아·애드리언은 완료 후 탐문 거점으로 복귀하고, 레오는 원래부터 있던 후속 체인(타임라인 미니게임 → 008a → 009)을 그대로 유지해 자유 탐문 구간에서 기존 선형 진행으로 자연스럽게 넘어가게 했다(레오의 방문 순서와 무관하게 안전 — 타임라인 미니게임 카드 데이터가 다른 두 용의자의 증거에 의존하지 않음을 확인함).

Playwright로 레오 스팟 진입 → 심문하기 → `week1-scene-008` 정상 진입, 그리고 윤민아 심문 종료 후 탐문 거점으로 정확히 복귀하는 것까지 확인.

### 아직 안 된 부분 (범위 밖 — 후속 작업)
- **`week1-scene-001`(출발 전 대화)은 허브와 미연결** — 여전히 순차 대사 그대로 두었다. 시티 도착 직후 곧바로 지도를 해금하는 §12.2의 "최초 진입" 축약 연출은 미구현.
- **증거 제시 / 진술 추궁 / 인물에 대해 묻기는 UI만 있고 실제 판정 로직이 없음** — 콘텐츠(evidence/rule)가 없는 이 시점에선 항상 기본 반응(`defaultPresentReaction`)만 나옴. §8(증거 제시 Correct/Partial/Wrong/Blocked)과 §9(진술 추궁)는 설계만 있고 미구현.
- **소프트 게이트는 이번 두 곳(전시장 진입, 다니엘 진술 종료)만 구현** — §10.3의 일반화된 "지금 정리한다 / 조사를 더 한다" 제안, §10.2 필수 조사 체크리스트 UI는 아직 없음(`phaseGoals`에 자리만 마련).
- **용의자 탐문은 "통짜 씬 단위" 자유 순서일 뿐, 씬 내부(4~9라운드)는 여전히 완전 순차** — §12.6이 궁극적으로 원하는 "진술별 압박·증거 제시 상호작용 노드" 수준의 세분화는 하지 않았다(기존 심문 로직을 안전하게 보존하기 위한 의도적 선택). §13.1이 말하는 "상호작용 노드로 분리"의 완전한 형태는 아님.
- Phase 1·4 외 나머지 4개 Phase(전시장 도난 전 자유 관람, 도난 직후 초기 조사, 현장 재검증, 최종 추궁)는 손대지 않음. `week1-scene-003`(전시장 진입 이후)부터 `005a/005b`(클레어·다니엘 진술)까지도 여전히 순차 그대로.
