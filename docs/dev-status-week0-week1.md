## 경제·옷가게·옷장 시스템 (신규 — *The Missing Key v1* §4/§5/§14 P0+P1 구현)

포인트(P) 재화, 완성 코디 프리셋 상점, 옷장 착용 시스템의 기반 계층을 새로 구현. 수사 진행에는 절대 관여하지 않고(포인트 지급/차감 없음), 비수사 미니게임·평일 콘텐츠의 장기 보상 재화로만 쓰인다는 설계 원칙을 그대로 따름.

### 신규 상태/데이터 파일
- `dev/state/economyState.js` — 포인트 잔액, `first_clear_only`/`chapter_capped` 보상 중복 방지, 거래 로그. `getPoints`/`canAfford`/`addPoints`/`spendPoints`/`claimReward`/`claimChapterCappedReward`.
- `dev/state/shopState.js` — 상점 해금 상태, 아이템별 해금(`unlockShopItems` 이펙트 + 선언적 `unlockConditions` 둘 다 지원), 구매 처리(`purchaseShopItem`).
- `dev/state/wardrobeState.js` — 보유/착용 코디, `resolveOutfitForScene`으로 대화 캐릭터 이미지에 착용 코디를 반영(업로드된 에셋이 없으면 기본 캐릭터 이미지로 자동 폴백).
- `dev/data/shopItems.js` — 0주차 4벌 + 1주차 4벌 코디 카탈로그(§5.6 가격표 그대로).
- `dev/caseFileState.js`의 `saveSlot`/`loadSlot`이 위 세 상태를 함께 스냅샷/복원하도록 확장.

### 신규 화면
- `/dev/shop/` — 상품 목록(NEW 배지·가격·소유 여부·잠금 사유), 입어보기 미리보기, 구매 확인 시트(보유/구매 후 잔액, 포인트 부족 안내), 구매 직후 착용 여부 선택.
- `/dev/wardrobe/` — 보유 코디 그리드, 탭하여 즉시 착용.
- 둘 다 별도 라우팅 화면으로 구현(§5.3, 모달 아님) — `sessionStorage.mkShopReturnUrl`로 진입 전 화면(씬+라인)으로 복귀.

### 게임 엔진 연동 (`dev/game/index.html`)
- 신규 이펙트 타입: `addPoints`(rewardId/policy 지원)·`spendPoints`·`unlockShop`·`unlockShopItem(s)`·`unlockWardrobe`·`purchaseOutfit`·`equipOutfit`.
- 상단바에 포인트 잔액 표시(`pointsUiIntroduced` 플래그로 첫 지급 전에는 숨김, 씬별 `hidePoints`로도 숨김 가능).
- CASE FILE 메뉴(`caseMenu.js`)에 옷가게/옷장 카드 추가(해금 후에만 노출), 미션 카드에 포인트 잔액 표시, `shopAccessBlocked` 플래그로 잠금·사유 표시(§5.3 — 아직 실제로 이 플래그를 세우는 심문/미니게임 콘텐츠는 없음, 훅만 마련).
- DEV 패널에 포인트/상점/옷장 디버그 버튼 추가(§24 일부: +100/-100P, 강제 해금, 전체 해금/소유, 초기화).

### Playwright 스모크 테스트로 확인된 플로우
로컬 정적 서버 + Chromium으로 다음을 실제 클릭/평가로 검증: 잠긴 상품의 사유 표시 → 해금 조건 충족 시 상품 노출 → 구매 확인창(부족 시 경고) → 구매 → 옷장 반영 → 착용 → CASE FILE 메뉴에 포인트/옷가게/옷장 노출. `week0-scene-shop-intro` 로드, 재구현된 `/dev/minigame-eastwood/`의 지도 미배치 시 안전한 폴백도 확인. (Supabase 자산 네트워크 요청은 이 샌드박스에서 프록시 제약으로 실패하지만 플레이스홀더로 정상 대체됨 — 실제 배포 환경에서는 해당되지 않음.)

### 아직 안 된 부분 (범위 밖 — 후속 작업)
- P2~P5: 반자유 탐색 허브(장소 이동·인물 행동 메뉴·대화 주제 상태), 증거 제시/진술 추궁을 상호작용 노드로 분리, 1주차 관광·수사 파트의 실제 콘텐츠 이관은 **아직 착수하지 않음**. 현재 1주차 23개 씬은 여전히 순차 대사 그대로.
- 옷가게 해금 조건에 쓰이는 `visitedCircularQuay`/`visitedTheRocksBoutique`/`week1CoreQuestionsResolved`/`harbourPhotoGradeS` 플래그는 카탈로그에 정의만 되어 있고, 이 값을 실제로 세팅하는 1주차 콘텐츠는 아직 없음(해당 상품은 계속 잠김 상태로 보임).
- 마이그레이션 보정 지급(§16.2, 기존 세이브에 500P 소급 지급)은 미구현 — 새 economy/shop/wardrobe 상태는 기존 세이브에 없으면 각 모듈의 `defaultXState()`로 자연스럽게 채워지지만, 소급 보상 로직 자체는 없음.
